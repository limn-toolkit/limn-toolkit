# ADR 036: A font is an artifact, and its version is the font's

- **Status:** Accepted, 2026-09-01. Implemented as the
  [limn-fonts](https://github.com/limn-toolkit/limn-fonts) repository (artifacts
  `limn-fonts-roboto`, `limn-fonts-noto-cjk`, `limn-fonts-noto-emoji`,
  `limn-fonts-noto-scripts`), the `limn-fonts-all` module here, and `FontStore`'s
  `limn/fonts/` classpath contract.
- **Date:** 2026-09-01

## Context

`limn-backend-lwjgl` vendored every face it renders with: four Roboto faces (1.9 MB), the
pan-CJK face (16 MB), colour emoji (10 MB) and the four complex-script faces (1.1 MB) —
29 MB of resources beside a quarter of a megabyte of code. Every toolkit release re-uploaded
those bytes to Maven Central inside the backend jar, every consumer re-downloaded them with
every upgrade, and none of them had changed: the CJK pin has not moved since the first
commit, and Roboto's build predates the repository.

The versions were the tell. `limn-backend-lwjgl 0.6.0` says nothing true about Noto Sans CJK
— that face's version is `Sans2.004`, a fact about the font that the toolkit's release
number erased. A byte that changes on the font's schedule was riding an artifact that
versions on the toolkit's.

Two facts made the cut cheap. `FontStore` already loads every face by classpath resource
path and degrades gracefully when one is absent (Roboto-only, `.notdef` boxes, a log line) —
the optional/graceful machinery predates this ADR. And a classpath spans jars, so which jar
carries a resource is invisible to the loader — the same property ADR 030 leaned on when the
FFmpeg payload split into classifier jars.

## Decision

**The faces live in their own repository, one Maven artifact per font, and each versions
with its font.** `limn-fonts-noto-cjk 2.004.x` IS Sans2.004; repackaging the same upstream
spends the third component. The jars are resources and a licence under `limn/fonts/` — no
code, no dependencies, and no minimum JVM beyond the lowest Gradle will record (a lesson the
first four releases paid for: metadata that inherited the build toolchain's "requires 21"
onto jars with no bytecode, refusing every consumer building for 17).

**Releases there are per module, and the tag is derived, never typed.** `versions.properties`
is the single place a version is written; on every push to main a workflow creates whatever
tags `<module>/v<version>` do not exist and starts one publish per new tag. Bumping the CJK
pin re-uploads 16 MB once, on the font's schedule, and touches no other face.

**Roboto is required; everything else is the application's choice.** The backend declares
`limn-fonts-roboto` as a runtime dependency — it is the default family and the last resort
every resolve degrades to, so `FontStore` fails construction with the artifact's coordinates
if a build excludes it; there is no Roboto-less mode. `limn-fonts-noto-scripts` is a default
runtime dependency too, at 1.1 MB: without it Arabic, Hebrew, Devanagari and Thai shape into
`.notdef` boxes out of the box, which would silently undo ADR 006 and ADR 032. The two
heavyweights — CJK and emoji, 26 MB together — follow the icon pack's rule: an application
that wants none of a pack pays for none of it.

**`limn-fonts-all` lives HERE, versioned with the toolkit.** It is a POM naming the three
fallback artifacts at the versions this release was tested with — because "which font
versions was this Limn tested against" is a fact about the toolkit, not about the fonts. A
POM carries no bytes, so re-publishing it every release costs nothing, and the heavy jars it
names are downloaded once per font version, not once per toolkit version.

**The digests stay on both sides.** The pins (upstream commit + SHA-256) moved to the fonts
repository with the fetch script; `VendoredFontsTest` here keeps its own digest table and
verifies the faces the artifacts deliver. That is deliberate redundancy: bumping a font
dependency is a one-line catalog diff that swaps megabytes of binary nobody reviews, and the
complex-script suite pins layout facts (conjuncts, reordering, contextual forms) that belong
to a particular build's GSUB. The test is what makes the one-line diff fail until the new
build is re-verified.

**Only Limn Menu Symbols stays vendored.** It is authored by this project, generated by
`scripts/generate-menu-symbols.py`, and its twenty glyphs must stay in step with what the
menu code draws: its version is the toolkit's, which is the exact criterion, inverted, that
sent every other face away.

`FontStore` probes `limn/fonts/<file>` first and the old `limn/backend/lwjgl/fonts/<file>`
second, so a region-variant CJK file placed at the long-documented old location keeps
working.

## Consequences

- The backend jar drops from ~29 MB to code plus three kilobytes of menu symbols. A release
  of Limn re-uploads no font; an application's dependency cache keeps each face across
  toolkit upgrades for as long as the font's own version stands.
- An application upgrading to this version **loses CJK and emoji unless it opts in** —
  one line (`limn-fonts-all`) or two (the faces it wants). The complex scripts and Roboto
  arrive transitively as before. The log line for an absent face names the artifact.
- The demo opts into everything: its i18n scenes draw CJK and emoji, and its fatJar is the
  screenshot rig for eleven READMEs.
- A font bump is now a normal dependency review here — catalog line, digest table, layout
  suite — instead of a 16 MB binary diff nobody could read.
- Two repositories must agree on what a face is, and the digest tables are that agreement,
  enforced by tests on both sides rather than by care.

## Alternatives considered

**One `limn-fonts` artifact carrying every face.** Rejected: it re-couples the versions the
split exists to separate — an emoji pin bump would re-ship 16 MB of CJK — and it makes the
26 MB opt-in indivisible from the 1.1 MB default.

**Fonts as classifier jars of the backend** (the shape the FFmpeg natives had first).
Rejected: classifiers share the module's version and POM, so the faces would still version
with the toolkit, which is the disease itself.

**`limn-fonts-all` in the fonts repository.** Rejected: with per-module versions it would
need a version and a release cadence of its own, and its whole content — "the set this Limn
was tested with" — is a claim only this repository can make.

**Keeping Roboto vendored.** Considered seriously (it is the one face with no optional
path), rejected because its 1.9 MB is as stable as the CJK face's 16 MB and the same
mechanism now exists either way; what "required" needed was not residence in the jar but a
loud construction-time failure, which `FontStore` provides.
